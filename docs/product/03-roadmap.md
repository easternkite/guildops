# GuildOps 로드맵 (MVP → V1)

- 문서 버전: 1.0
- 작성일: 2026-02-11
- 기준일: 2026-02-11 (수)
- 범위: 제품/엔지니어링 통합 로드맵

## 1) 로드맵 목표

1. MVP 안정화: 현재 스캐폴드 기능을 운영 가능한 품질로 고도화.
2. V1 출시: 길드 운영 핵심 루프(멤버-출석-공지-보상)를 데이터 기반으로 완성.
3. 수익화 준비: 플랜/과금/계측 기반 확보.

## 2) 단계별 마일스톤

| 단계 | 기간 | 목표 | Exit Criteria |
|---|---|---|---|
| Phase 0 - Stabilize MVP | 2026-02-16 ~ 2026-03-13 (4주) | 코어 도메인 DB 일원화, 권한 정책 통일 | lint/test/build 통과, 운영 시나리오 E2E 5개 통과 |
| Phase 1 - Productize Core | 2026-03-16 ~ 2026-04-24 (6주) | 운영자 UI/워크플로 개선, 감사 로그 실사용 | WAU 20개 길드, 주간 재방문율 45% |
| Phase 2 - V1 Readiness | 2026-04-27 ~ 2026-06-05 (6주) | 리포팅, 과금 베타, 온보딩 자동화 | 유료 베타 10개 길드, Free→Paid 5% |

## 3) 기능 우선순위

### 3.1 Must / Should / Could

| 우선순위 | 기능 | 현재 상태 | 목표 단계 |
|---|---|---|---|
| Must | Attendance CRUD + Check-in 권한정책 | 동작 중(핵심 강점) | Phase 0 강화 |
| Must | Members/Events/Announcements DB 기반 전환 | 일부 인메모리 | Phase 0 |
| Must | Audit log 실기록 및 조회 UI | 스캐폴드 | Phase 1 |
| Must | 운영 대시보드 KPI 요약 | 플레이스홀더 | Phase 1 |
| Should | Rewards 정산 워크플로 | 스캐폴드 | Phase 1 |

| Could | 모바일 최적화 운영 패널 | 미구현 | Phase 2 이후 |

## 5) Heartbeat Queue 매핑 (실행 정합성)

| Heartbeat Queue | 로드맵 항목 매핑 | 상태 (2026-02-11) |
|---|---|---|
| Q-001~Q-002 (마이그레이션/드리프트) | Phase 0 · W1 데이터/운영 안정화 | 완료 |
| Q-003~Q-005 (권한/출석 UX) | Phase 0 · W2~W3 API 안정화 + UX 개선 | 완료 |
| Q-006 (관측성 baseline) | Phase 0 · W4 릴리즈 체크리스트 기반 | 완료(문서) |
| Q-007~Q-008 (도메인 Prisma 전환/검증) | Phase 0 · W1~W2 DB 일원화 목표 | 완료 |
| Q-009~Q-012 (product docs 정합화) | Phase 0 계획-실행 동기화 트랙 | 진행/완료 |

메모:
- Heartbeat Queue는 로드맵의 **선행 실행 단위**로 운영하며, 각 Q 완료 시 로드맵 해당 섹션(주차/리스크/체크리스트)을 함께 갱신한다.
- 다음 사이클에서는 Q 항목을 주차(W1~W4) 기준 태그로 생성해 로드맵 추적성을 강화한다.

## 7) Go/No-Go 체크리스트

### MVP 안정화(Phase 0) 릴리즈 체크
- [ ] `pnpm lint`, `pnpm test`, `pnpm build` 모두 통과
- [ ] Members/Events/Announcements가 DB 기반 CRUD로 전환
- [ ] Attendance 권한 정책 회귀 테스트 통과
- [ ] 최소 3개 실사용 길드 파일럿 운영

### V1 출시 체크
- [ ] 운영 대시보드에서 주간 KPI(출석률/활성멤버/공지 도달) 조회 가능
- [ ] 과금 플랜 게이트 및 사용량 측정 동작
- [ ] 무료→유료 전환 퍼널 데이터 수집 가능
- [ ] 온콜/장애 대응 런북 최신화
